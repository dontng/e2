## 一条错误怎样入库

同一错译可能同时命中多条机制，但只设一个“首个失控点”为主归档，其他目录以交叉引用保留。例如 `district → restriction` 先是词形抢答，随后中文又把剩余句子补成故事；主记录进词形库，中文补空库只记录它造成的扩散。这样既不漏掉链条，也不把同一错误重复计算成四次失败。

每条记录必须包含英语锚点、首次反应、失控机制、下次识别信号和来源。只有真实首译或真实作答才能进入 `cases.md`；教学例句只能进入 `drills.md`，不能倒填成历史错误。

## 执行顺序

1. 新 Daily 或真题出现错误后，先定位第一个失控点，并追加到对应 `cases.md`。
2. 若当天已有充分讲解，不再写第二篇长解释；从 `drills.md` 取 3–10 个闭卷新语境。
3. 作答后把每个控制点记入 `review-log.md`：`F` 错误、`H` 正确但明显犹豫、`S` 直接成功。
4. 后续按 D1、D3、D7、D14、D30 换语境复测。出现 `F` 回到 D1；第三次沿同一路径失败，只加窄对比或改变任务形式。
5. 至少跨 14 天三次 `S`，含一次无选项、无中文提示的新语境，才从活动队列退出。完整低熟悉真题中的自然命中是更强证据。

## 这套系统怎样服务分数

专项全对只能证明局部动作建立了，不能替代整卷。65+ 按阶段门槛验收，75+ 按最终目标验收：最近五次低熟悉、完整、正式限时的英语二测试中，至少三次达到相应阈值，另外两次没有系统性超时、大面积留白或同一根因连续坍塌，才称为可稳定复现。

用户只负责当次阅读和作答。归类、到期判断、复测选材、状态更新与退出决定由 Codex 维护。
