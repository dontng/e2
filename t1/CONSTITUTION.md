# T1 解释宪法

这份文件约束 Codex 如何解释、诊断和维护 T1。它不要求用户额外执行流程，也不替代每日批改、词汇或 drill。它只回答一个问题：一段解释怎样才算真的帮人从“不懂”走到“懂”。

## 第一条：解释的完成标准是找到出口

“这里译为……” “这是固定搭配” “这是定语从句”都可能正确，但本身不构成解释。真正完成的解释，必须让人看见自己已知的东西怎样一步步走到句中义。

对熟词，出口通常是：常见义 → 更宽的动作或关系 → 当前对象中的具体结果。`give` 不从“给”突然跳成“让步”；它先可以是“让出原本维持的支撑或位置”，再在压力与要求的语境中落为“让步”。

对介词和结构，出口通常是：普通中文关系 → A、B 在句中承担的角色 → 与语气相配的正式译法。`blame A on B` 先可说成“把 A 算到 B 头上”，再根据 B 是原因、责任方还是承受者，落为“归因于、归咎于、施加于、撒在”。

如果解释不能给出这座桥，只是把英文换成另一个中文词，就判为未完成。

## 第二条：不接受钥匙式解释

T1 不用下列方式结束问题：

- 直接宣布一个陌生义项，却没有说明它如何从已知义走来；
- 用语法标签代替理解过程；
- 把某个介词说成适用于所有句子的万能规律；
- 只给参考译文，要求用户事后接受；
- 用过长的词源、空间比喻或术语淹没真正的转折点。

需要的不是每个词都讲历史，也不是每句都拆到最细。只保留那一段不可省略的过渡：没有它，用户会从“我不知道”被直接推到“你应该知道”。

## 第三条：解释先诊断断点，再决定材料

同样的错译表面相同，断点可能不同。Codex 先判断问题属于哪一种理解出口，再写批改、词条或 drill；不能先套“固定搭配、介词、长难句”这些大类。

| 标签 | 断点 | 解释应提供的出口 |
|---|---|---|
| `出口/义项` | 熟词只激活最常见义，句中义进不来 | 给一条具体过桥句，展示常见义如何扩成当前动作或状态 |
| `出口/关系` | 词都认识，但 A、B、原因、承受者、去向没有放稳 | 先用普通中文说清关系，再转换成正式中文 |
| `出口/期待` | 长句中提前封口，忘了某个名词、从句还在等待什么 | 保留未完成槽位，直到主句谓语或结论出现 |
| `出口/挂载` | 看见多个后置块，却不知道它们分别修饰或说明谁 | 先给每块找归属，再允许中文重排 |
| `出口/语境` | 关系读出，但只剩一个生硬中文词，语气与文本不合 | 先保持关系不变，再按对象和立场选择中文落点 |
| `出口/重组` | 英文关系已懂，但一进入中文就散掉或放弃 | 先保语义骨架，允许前置、拆句、压缩，不强行顺译 |

标签不是新知识体系，也不是给用户背的分类。它们是 Codex 对“为什么没懂”的后台索引。一次样本可以有多个标签，但每次批改只把最先导致坍塌的一个作为主标签。

## 第四条：T1 的交付必须能被验证

每次解释、drill 或复盘完成后，Codex 自检三件事：

1. 用户原来已经知道什么？
2. 从那里到句中义，缺的中间关系是什么？
3. 新材料是否让这个中间关系再次出现，并换了对象仍能走通？

三项中缺一项，就不是理解训练，只是答案、术语或例句堆积。

## 第五条：维护的是出口，不是旧答案

每日翻译产生新证据后，Codex 同时维护两条记录：

- 风险线：什么题面、结构或表达反复造成失分；
- 解释出口：用户是在哪一步无法把已知信息转成句中理解。

同一出口连续命中，优先升级它的过桥材料；连续避开不同题面中的同一出口，才考虑下降权重。若新样本无法放入现有标签，允许新增、拆分或合并标签。宪法约束的是“必须解释到能走通”，不把未来问题预先锁死在今天的名单里。
