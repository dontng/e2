# Codex Handoff

这个文件用于不同 Codex 入口之间交接：Codex App、Codex CLI、GPT App 读取同一套项目状态后，应能知道下一步该怎么接。

## 用户常用启动语

```text
接管 english2-daily 今天的批改闭环。
```

```text
补跑 english2-daily 今天的晚间闭环启动。
```

```text
先补 dayXX 的未闭环问题。
```

```text
根据最近几天批改，给我今晚 10-15 分钟最低可执行训练。
```

## 接管时的最小读取集

1. `README.md`
2. `AGENTS.md`
3. `REVIEW.md`
4. `reviews/<current-week>.md`
5. `codex/STATE.md`
6. `codex/LOG.md`
7. 必要的 `src/...day...md`

## 接管输出格式

优先短而可执行：

```text
今晚入口：...
积压状态：...
最高价值问题：...
你需要亲自确认：...
Codex 可以代处理：...
最低可执行版本：...
```

## 写回原则

默认先给建议，不直接写回。

只有用户明确说“接管处理”“写回”“更新周总结”“提交”等，才修改仓库文件。

修改优先级：

1. 周总结中的未闭环问题和批改质量审计。
2. 每日文件中的 Takeaways、Vocab、Phrases 覆盖缺口。
3. `REVIEW.md` 的当前审计范围。
4. `codex/LOG.md` 的交付记录。

## 成功标准

一次接管成功，不是因为产出很多文字，而是因为至少推进了一个真实提分问题：

- 用户更清楚自己哪里没懂。
- 一个反复错误被命名并转化为动作。
- 一个周总结中的观察点被验证、更新或关闭。
- 一个积压 day 被恢复到可继续推进的状态。
