# Codex Interaction Workspace

这个目录是 english2-daily 的 Codex 交互区。它不是每日正文，也不是归档；它是 Codex App、Codex CLI 和用户之间共享的“地址块”。

## 目的

本项目的目标不是完成一次翻译批改，而是把批改后仍没解决的问题继续推进，直到形成可迁移的提分动作。

当前长期目标：英二从 39 提升到 65+。

Codex 在这里维护三类信息：

- **理解需求**：用户看完批改后仍可能没懂的结构、词义、搭配、逻辑关系。
- **提分需求**：这些问题下次怎么少扣分，应该形成什么稳定动作。
- **交付记录**：Codex 已经整理、挖掘、推进了什么，下一步还欠什么。

## 使用边界

- `src/` 仍然保存每日句子、原译和批改正文。
- `reviews/` 仍然保存周总结和批改质量审计。
- `REVIEW.md` 仍然是当前审计入口。
- 本目录只保存 Codex 交互状态、长期策略、积压和交付记录。

Codex 不应把每日批改正文堆到这里；这里记录的是“批改之后还要解决什么”。

## 入口文件

- `STATE.md`：当前学习协议、运行方式、积压策略。
- `BACKLOG.md`：长期能力问题台账，只记录还要追踪什么。
- `notes/`：句子讨论精华，按周保存；这是给用户复读和给 Codex 接管时快速找训练材料的入口。
- `LOG.md`：Codex 每次重要接管后的交付记录。

## Codex 进入规则

进入项目后仍按主接口读取：

1. `README.md`
2. `AGENTS.md`
3. `REVIEW.md`
4. 当前 `reviews/<week>.md`
5. 必要的 `src/...day...md`
6. 本目录下的 `codex/STATE.md`、`codex/BACKLOG.md`、`codex/notes/<week>.md` 和 `codex/LOG.md`

读取本目录时，重点回答：

- 最近真正未闭环的问题是什么？
- 今晚最值钱的一个推进点是什么？
- Codex 已经交付了什么，哪些仍需用户确认？

## notes 写法

`notes/` 不是聊天记录，也不是树状索引。每条只保留四件事：

1. 用户当时怎么卡住。
2. 这个卡点真正暴露什么能力问题。
3. 下次看到同类词或结构时怎么做。
4. 用哪些例句验收是否真的会了。

英二翻译当前最值钱的材料只有两类：单词和例句。`notes/` 必须优先服务这两类，而不是服务形式完整。
