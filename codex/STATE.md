# Codex State

## 长期目标

用户是在职备考英二，目标是从 39 提升到 65+。

这个项目不追求“每天打卡漂亮”，而追求每次批改后都能把真实能力问题推进一步：看懂、说清、下次少错。

## 核心判断

普通批改只增加“这句话怎么翻”的信息；真正的提分来自批改后的二次处理：

- 哪个结构其实还没懂？
- 哪个词或短语只是表面认识？
- 哪个误判会在下一题继续扣分？
- 哪个 Takeaway 能变成下一次翻译前的动作？

Codex 的任务是把批改内容转化为理解需求和提分需求。

## 每晚运行方式

每天北京时间 20:10，Codex App 的已安排任务会尝试在当前线程中读取仓库并输出晚间闭环启动清单。

若笔记本未在线或任务错过，用户可以补发：

```text
补跑 english2-daily 今天的晚间闭环启动。
```

若用户准备正式开始，可以发：

```text
接管 english2-daily 今天的批改闭环。
```

## 输出优先级

每次接管或补跑，优先输出：

1. 今天或最近积压的 day 文件状态。
2. 最高价值的 2-4 个未闭环能力点。
3. 用户今晚必须亲自确认的理解点。
4. Codex/GPT 可以直接处理的 Markdown 或复盘工作。
5. 如果很累，给出 10-15 分钟最低可执行版本。

## 长期高危问题

当前已暴露的高危能力点：

- **主干定位**：长句先抓真正主谓和核心谓语链。
- **搭配合读**：固定搭配先整体判方向，不逐词硬拼。
- **词形辨认**：避免只看前三四个字母猜词，尤其是 `comp-`、`imp-`、`dis-` 一类。
- **抽象词落点**：把 `beliefs`、`variable`、`implication`、`inherently` 这类词落成句中功能。
- **结构关系**：看清修饰链、指代和从句层级，再决定中文。

## 夜班和积压策略

用户可能有夜班周，三四个月一次，一周内可能连续多天无法坐到笔记本前。

这种情况下，Codex 不应责备或催促，而应做无责恢复：

- 检查最近 7 天或 `REVIEW.md` 当前范围后的 day 状态。
- 找出已入库但未批改、已批改但未沉淀、周总结未同步、`REVIEW.md` 未更新的积压。
- 不要求一晚补完。
- 优先建议“今晚只解决一个最值钱的问题”。

## 不做什么

- 不把任务降级成每日提醒。
- 不默认写回仓库，除非用户明确让 Codex 接管处理。
- 不全仓库扫描。
- 不为了形式完整而凑 Vocab/Phrases/Takeaways。
